## 零、登录功能真实逻辑（先搞懂再测）

从代码和数据库确认的事实：

| 事实 | 来源 | 测试意义 |
|------|------|----------|
| 验证码开关开启（`sys.account.captchaEnabled=true`） | sys_config 表 | 不传验证码必然失败 |
| 验证码存 Redis，key=`captcha_codes:{uuid}` | SysLoginService | 测试可直接从 Redis 读验证码 |
| 验证码**大小写不敏感**（`equalsIgnoreCase`） | 源码 | 大小写算同一个验证码 |
| 密码长度 5~20 | UserConstants | 边界值：4/5/20/21 |
| 用户名长度 2~20 | UserConstants | 边界值 |
| 有 IP 黑名单校验 | 源码 | 安全测试点 |
| **无连续输错锁定机制** | 源码未发现 | 潜在安全Bug |

**测试必备技巧：从 Redis 读验证码（接口测试的核心）**

验证码是图片，人眼看太慢，接口自动化又没法输图片。其实 RuoYi 把验证码明文存在 Redis 里，测试时直接读出来：

```bash
# 1. 先调接口拿 uuid
curl -s http://localhost:8080/captchaImage | grep -o '"uuid":"[^"]*"'

# 2. 用 redis-cli 读验证码明文
"C:/Program Files/Redis/redis-cli.exe" get "captcha_codes:{刚才的uuid}"

# 3. 拿到明文后，就能自动化调登录接口了
```

> 这一步让你从"手工点页面"升级到"接口自动化"，是测试工程师和普通点点点选手的分水岭。

## 七、接口测试（Postman，10条）

接口地址：`POST http://localhost:8080/login`，请求体 `{"username","password","code","uuid"}`

| 编号 | 用例标题 | 请求 | 预期结果 |
|------|----------|------|----------|
| API_001 | 正常登录 | 正确4参数 | HTTP 200，code=200，msg="操作成功"，返回token |
| API_002 | 缺username字段 | 不传username | 返回错误，提示参数缺失 |
| API_003 | 缺password字段 | 不传password | 返回错误 |
| API_004 | 缺code字段 | 不传code | 返回"验证码错误/已失效" |
| API_005 | 缺uuid字段 | 不传uuid | 返回验证码错误 |
| API_006 | username为空串 | username="" | 返回错误 |
| API_007 | password长度4 | password="1234" | 返回密码长度不符 |
| API_008 | 错误验证码 | code="0000" | 返回"验证码错误" |
| API_009 | 不存在的用户 | username="nouser" | 返回"用户不存在" |
| API_010 | 停用用户 | username=停用账号 | 返回"账号已停用" |

**接口测试自动化技巧**：写个脚本，先 `GET /captchaImage` 拿 uuid，再 `redis-cli get captcha_codes:{uuid}` 拿验证码明文，然后自动 `POST /login`。三步串起来，登录接口就能全自动回归。

## 九、数据库验证 SQL

```sql
-- 1. 登录日志（每次登录都记录，含成功/失败）
SELECT user_name, ipaddr, status, msg, login_time
FROM sys_logininfor ORDER BY login_time DESC LIMIT 10;

-- 2. 验证 admin 密码是密文存储
SELECT user_name, LEFT(password, 20) AS pwd_prefix FROM sys_user WHERE user_name='admin';
-- 预期：以 $2a$10$ 开头（BCrypt），不是明文 admin123

-- 3. 验证验证码开关
SELECT config_value FROM sys_config WHERE config_key='sys.account.captchaEnabled';
```
