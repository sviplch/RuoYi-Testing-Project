# 07 — 实战：端到端场景测试（场景法）

> 前面三个模块（登录、用户管理、角色管理）都是**单模块**的用例。这一份用**场景法**把模块串起来，测一条完整的业务流。这是面试里区分"只会测单个功能"和"懂系统整体"的关键。

---

## 一、什么是场景法，为什么重要

**场景法** = 模拟真实用户的操作路径，把多个功能点串成一条完整流程，验证整条链路是否走通。

- 等价类/边界值测的是**单个输入框**，是"点"
- 场景法测的是**完整业务流程**，是"线"
- 面试官问"你怎么测一个功能"，高级答法就是"我先用场景法走一遍主流程，再对关键字段做等价类和边界值"

**端到端场景的价值**：能发现单模块测试发现不了的 Bug——比如"用户能建成功、角色能配成功、但配完之后登录进去菜单就是出不来"，这种**跨模块衔接问题**只有场景法能测出来。

---

## 二、场景一：完整用户生命周期（主场景，必测）

**一句话描述**：新建角色 → 配数据权限和菜单 → 新建用户并分配角色 → 用该用户登录 → 验证菜单和数据范围 → 停用用户 → 验证登录失败 → 启用 → 删除。

### 前置条件

- 用 admin/admin123 登录系统
- 部门结构已存在（研发部 103、测试组 106、市场部 105）

### 测试步骤与检查点

| 步骤 | 操作 | 检查点 | SQL 验证 |
|------|------|--------|----------|
| 1 | 角色管理 → 新增角色"测试专员"，权限字符 test_staff，数据权限选"本部门"(3)，勾选"用户管理"菜单 | 新增成功 | `SELECT * FROM sys_role WHERE role_key='test_staff'` |
| 2 | 确认角色-菜单已关联 | 用户管理菜单已勾选 | `sys_role_menu` 有记录 |
| 3 | 用户管理 → 新增用户 test01，部门选"研发部"，分配角色"测试专员" | 新增成功 | `sys_user` 有 test01，`sys_user_role` 有关联 |
| 4 | 退出 admin，用 test01 登录 | 登录成功 | - |
| 5 | 查看左侧菜单 | **只显示"用户管理"，看不到角色/部门等未授权菜单** | - |
| 6 | 进入用户管理列表 | **只看到"研发部"的用户，看不到市场部**（数据权限=本部门） | 对比 admin 视图行数 |
| 7 | 尝试访问角色管理 | 无权限（403 或菜单不显示） | - |
| 8 | 退出 test01，用 admin 停用 test01 | 停用成功 | `status='1'` |
| 9 | 用 test01 再登录 | **登录失败，提示"用户已封禁，请联系管理员"** | - |
| 10 | admin 启用 test01，再登录 | 登录成功 | - |
| 11 | admin 删除 test01 | 删除成功（逻辑删除） | `del_flag='2'` |

**这个场景串起了 3 个模块的 11 个动作**，面试讲这一条就能证明你理解了系统的完整闭环。

## 三、场景二：数据权限越权验证（安全场景）

**一句话描述**：验证一个"本部门"数据权限的用户，无法看到或操作其他部门的数据。

| 步骤 | 操作 | 检查点 |
|------|------|--------|
| 1 | admin 建角色 role_self，数据权限=本部门(3)，分配用户管理菜单 | 建成功 |
| 2 | 建用户 self01（研发部）、self02（市场部），都分配 role_self | 建成功 |
| 3 | 用 self01 登录查用户列表 | 只看到研发部用户，**看不到 self02** |
| 4 | self01 尝试直接调 `GET /system/user/list` 且人为带 market 部门的 deptId 参数 | 仍只返回本部门数据（后端强制过滤，前端参数无效） |
| 5 | self01 尝试修改市场部用户的接口 `PUT /system/user` | 返回"无权限"或数据不可见 |
| 6 | self01 尝试调角色管理接口 `GET /system/role/list` | 403（无按钮权限） |

**面试讲法**：这就是越权测试——横向越权（改别人的数据）+ 纵向越权（低权限访问高权限接口）。

---

## 四、场景三：权限变更即时生效验证（回归场景）

**一句话描述**：用户登录状态下，admin 修改其角色权限，验证是否即时生效。

| 步骤 | 操作 | 检查点 |
|------|------|--------|
| 1 | 用户 test01 已登录（角色有"用户管理"菜单） | - |
| 2 | admin 修改 test01 的角色，**去掉**"用户管理"菜单权限 | 修改成功 |
| 3 | test01 刷新页面 | **用户管理菜单消失，或点击报 403**（源码 refreshPermissionByRoleId 应即时生效） |
| 4 | admin 停用 test01 的角色 | - |
| 5 | test01 再操作 | 该角色对应权限失效 |

> 这个场景测的是"权限变更的实时性"。很多系统要重新登录才生效，RuoYi 源码里做了在线权限刷新，测一测到底即时不即时——**发现不即时就是 Bug**。

---

## 五、场景四：异常恢复场景

**一句话描述**：操作到一半中断，数据是否一致。

| 步骤 | 操作 | 检查点 |
|------|------|--------|
| 1 | 新增用户填到一半，关闭弹窗 | 不产生数据 |
| 2 | 新增用户提交后，立即断网/刷新 | 数据要么完整落库，要么完全没落库（事务性） |
| 3 | 删除用户时点"取消" | 用户仍在 |
| 4 | 给角色分配菜单时，勾一半点取消 | 角色菜单不变 |

## 六、场景法用例怎么写进「测试用例表」

场景法不是只能口头描述，也能落成标准用例。格式是「一个场景拆成多条用例，每条有明确的预期」：

| 编号 | 用例标题 | 优先级 | 前置条件 | 测试步骤 | 预期结果 |
|------|----------|--------|----------|----------|----------|
| E2E_001 | 新角色新用户全流程走通 | 高 | admin 登录 | 建角色→配权限→建用户→分角色→用户登录 | 用户登录成功，看到对应菜单 |
| E2E_002 | 新用户数据权限范围正确 | 高 | E2E_001 完成 | test01 登录查用户列表 | 只显示本部门用户 |
| E2E_003 | 无菜单权限不可见 | 高 | E2E_001 完成 | test01 访问角色管理 | 菜单不显示或 403 |
| E2E_004 | 停用后登录被拒 | 高 | E2E_001 完成 | admin 停用 test01，test01 登录 | 提示"用户已封禁，请联系管理员" |
| E2E_005 | 越权修改他人数据被拒 | 高 | self01 登录 | self01 改市场部用户 | 无权限，数据不变 |

## 七、端到端测试总结

| 场景 | 覆盖能力 |
|------|----------|
| 场景一：用户生命周期 | 模块串联、正向主流程 |
| 场景二：数据权限越权 | 横向/纵向越权测试 |
| 场景三：权限变更实时性 | 回归、边界 |
| 场景四：异常恢复 | 事务一致性、容错 |

**核心价值**：端到端场景让你从"测功能"升级到"测系统"。面试时，别人只会说"我测了登录、测了用户管理"，你能说：

> "除了单模块测试，我还用场景法设计了几条端到端用例。比如一条完整的用户生命周期——建角色、配数据权限、建用户、分配角色、登录验证菜单和数据范围、停用后验证登录被拒。这条用例串起了登录、用户管理、角色管理三个模块，还顺带验证了数据权限越权。跨模块的衔接问题，只有这种场景法才能测出来。"
